# Bili Pin Roadmap

## 当前状态
- **当前版本**：`v1.2.1`
- **当前产品形态**：动态页置顶栏已从早期“展开/收起”演进为可纵向拉伸、可滚动、可持久化高度的容器；置顶入口覆盖动态推荐横条、动态卡片三点菜单、动态页 hover 用户资料卡、搜索页用户结果、空间页和视频页关注菜单；配置同步以 `chrome.storage.sync` 为主、`chrome.storage.local` 为镜像与回退，置顶列表使用压缩状态降低 sync 单 key 配额压力；扩展图标弹窗提供同步摘要。
- **近期文档维护**：`2026-05-18` 已重写 `AGENTS.md` 为当前 AI 维护手册，并同步 `README.md`、`docs/prd.md`、`docs/roadmap.md` 中关于搜索页、hover 用户资料卡和当前版本的旧口径。后续新增功能或实现调整时，需要继续同步更新本文件和 `AGENTS.md`。

## 已完成版本

### v1.2.1
- **运行时修复**：
  - 规范化 B 站头像 URL 为 HTTPS，并将持久化头像短引用压缩为可还原的 B 站 face 文件标识。
  - 新增置顶列表 v3 压缩状态，读取时合并 sync/local 的 v3、v2、v1，避免多设备延迟升级时旧状态误删新数据。
  - v2/v1 旧格式仅在容量内继续同步回写；主同步写满时改为页面 toast 提示，避免只在 console 中静默失败。

### v1.2.0
- **多入口置顶能力收敛**：
  - 正式合并动态页 hover 用户资料卡置顶入口，从 `.bili-user-profile` 中提取 space 链接真实 `mid`，并在资料卡按钮区注入“置顶UP主 / 取消置顶”。
  - 正式合并搜索页用户结果置顶入口，支持综合搜索用户卡片 `.b-user-video-card` 和用户 Tab 卡片 `.b-user-info-card`。
  - 将 storage bridge 匹配范围扩展到搜索页，确保搜索页按钮复用同一套 `chrome.storage.sync/local` 状态链路。
  - 清理从原生关注按钮克隆时可能继承的禁用态，并收敛搜索页和资料卡置顶按钮视觉样式。
- **开发流程文档**：
  - 将本地页面快照和 Computer Use 观察边界写入维护规范，明确隐私、DOM 证据和账号安全要求。

### v1.1.7
- **搜索页用户结果置顶**：
  - 新增 `entrypoints/search.content.ts` 和 `src/ui/searchUserPin.ts`。
  - 从用户卡片中的 `space.bilibili.com/{mid}` 链接提取真实 mid，并在 `.user-actions` 中追加置顶按钮。
  - 搜索结果异步刷新时通过局部观察和单帧重扫保持按钮状态同步。

### v1.1.6
- **动态页 hover 用户资料卡置顶**：
  - 新增 `src/ui/dynamicUserProfilePin.ts`。
  - 监听挂在 `body` 下的 `.bili-user-profile`，从资料卡头像/昵称链接提取真实 mid，并在 footer 中注入置顶按钮。
  - 对单个资料卡做局部 observer，资料卡移除时主动清理。

### v1.1.5
- **API 拦截收紧**：
  - fetch 拦截只在 URL 改写阶段捕获异常，真实网络错误保持页面原语义，避免扩展误触发第二次请求。
  - XHR 响应提取改为追加 `loadend` 监听，不覆盖页面自己的 `onreadystatechange`。

### v1.1.4
- **长期运行风险收敛**：
  - 关注时间注入改为优先绑定关注列表容器，避免长期监听整页 body subtree。
  - 视频页 popover observer 在弹层节点移除时主动断开。
  - 动态卡片菜单、推荐横条按钮刷新合并到帧，减少空转和重复重刷。

### v1.1.3
- **置顶栏高度持久化收敛**：
  - 修复刷新后高度逐次变高的问题，原因是旧逻辑曾把 `.bili-pin-bar__list` 的渲染总高度误写回 CSS `height`。
  - 修复手动拉伸后的高度刷新后退回默认两行的问题，原因是中途返工把“当前显示高度”和“已持久化高度”混在一起，导致保存链路被短路。
  - 最终方案收敛为：初始化时读取已保存高度；拖拽结束 (`pointerup` / `pointercancel`) 时串行写入最终高度；不再依赖 `ResizeObserver`、防抖定时器或多份 DOM dataset 影子状态回写。
- **版本单一真源**：
  - `wxt.config.ts` 中的 manifest 版本号改为直接读取 `package.json`，避免项目出现两份版本号。

### v1.1.2
- **置顶栏交互升级**：
  - 将动态页置顶栏从固定两态的“展开/收起”切换为可自由纵向拉伸的滚动容器。
  - 新增底部正中央拖拽手柄；置顶头像过多时可通过纵向滚动浏览完整列表。
  - 新增置顶栏高度的 `sync/local` 镜像存储与时间戳状态，兼容旧版展开状态作为一次性迁移回退。

### v1.1.1
- **同步能力完善**：
  - 修复跨设备同步各自分叉的问题；为置顶列表引入带时间戳的同步状态和删除墓碑，跨设备读取时按最新操作时间合并，而不是整块互相覆盖。
  - 置顶栏展开状态也改为按更新时间收敛，并通过 `chrome.storage.onChanged` 桥接让已打开页面能主动响应远端 `sync` 变化。
  - 支持从 `config/manifest-key.txt` 读取固定 `manifest.key`，保证两台电脑本地调试时保持相同扩展 ID。
  - 扩展图标弹窗调整为简洁同步摘要，只展示头像数量和最后同步时间，并修复 MV3 下内联脚本不执行导致的空白问题。
  - 收尾清理：移除页面 `localStorage` 存储兜底，收敛生产环境调试桥与控制台诊断输出，并补上 `npm run typecheck`。

### v1.1.0
- **配置同步**：
  - 新增 `chrome.storage.sync` 配置同步能力，置顶列表与置顶栏展开状态支持同账号浏览器同步。
  - 升级时自动将旧版仅保存在 `chrome.storage.local` 的配置迁移到同步存储，避免更新后被空同步数据覆盖。
  - 保留 `chrome.storage.local` 镜像写入，作为同机回退与兼容层。

### v1.0.4
- **权限与代码优化**：
  - 移除 `host_permissions` 权限申请（Manifest V3 内容脚本无需此权限）。
  - 收窄 API 拦截脚本的注入范围（仅限视频页），减少对无关页面的影响。
  - 清理废弃的 API 调用代码。

### v1.0.3
- **Bug Fixes**:
  - 修复视频播放页长时间挂机后因 `MutationObserver` 死循环导致的内存溢出 (OOM) 崩溃。

### v1.0.2 
- **稳定性 / 性能（长时间挂着不崩）**：
  - 收窄 API 拦截范围：仅对 `portal/uplist/feed/relation` 等我们真正依赖的接口解析 JSON，避免对所有 `api.bilibili.com` 响应做解析导致长期性能/内存压力累积。
  - 增加缓存上限与裁剪策略：限制 UP 信息缓存与 portal 列表长度，避免长时间运行下缓存无边界增长。
  - 增强关注时间兼容性：将 `mid -> mtime` 关注时间独立缓存，避免在关注列表很大时因 UP 信息缓存裁剪导致“关注时间不显示”。
  - 单例保护：防止极端情况下重复初始化 API 拦截器导致多重 wrap。

### v1.0.1 
- **Bug Fixes**:
  - 修复了动态页推荐栏“加载更多”后，新加载的 UP 主置顶按钮无法点击（置灰）的问题（通过拦截 `v1/uplist` 接口解决）。
  - 修复了 SPA 环境下多次注入导致的 `MutationObserver` 和全局事件监听器内存泄漏问题。

### v1.0.0 
- **动态页置顶栏（首版）**：在 `https://t.bilibili.com/` 注入“置顶动态”栏，首版交互是展开/收起与显示总数；这一形态后来在 `v1.1.2` 演进为可拉伸高度容器。
- **全站置顶入口**：
  - 动态页推荐横条：注入图钉按钮。
  - 动态卡片菜单：注入置顶选项。
  - 个人空间页/视频播放页：在“已关注”菜单中注入置顶选项。
- **核心交互**：
  - 点击置顶头像切换 Feed（自动处理 UP 是否在推荐栏的情况）。
  - 置顶栏支持拖拽排序（即时保存）。
  - 选中高亮与筛选态 UI（隐藏 Tabs）。
- **辅助功能**：
  - 个人空间关注列表显示“关注时间”。
  - 数据本地持久化（首版为 `chrome.storage.local`，后续在 `v1.1.0` 升级为 `sync` 主存储 + `local` 镜像）。
