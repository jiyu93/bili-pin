# Bili Pin 产品说明

Bili Pin 是一个 Bilibili Chrome MV3 扩展，让用户在动态首页固定最关心的 UP 主，减少低频更新被推荐横条遗漏的问题。纯前端实现，无后端服务。

## 当前功能与行为

| 功能 | 用户可见行为 |
|---|---|
| 动态页置顶栏 | 在 `t.bilibili.com` 中栏原生推荐横条上方展示置顶头像，横条尚未加载时等待，页面重建后自动恢复位置；点击筛选 UP 动态，拖拽排序，纵向拉伸高度，栏内滚动。列表、顺序和高度刷新后保留。 |
| 多页面置顶入口 | 动态推荐横条、动态卡片三点菜单、hover 用户资料卡、搜索综合/用户 Tab 卡片、空间页及视频页“已关注”菜单均可置顶或取消；已打开页面的状态同步刷新。 |
| Feed 切换 | UP 在推荐横条内时复用原生点击，不在横条内时改写 feed 请求的 `host_mid`，由 B 站渲染；点击原生推荐横条或 Tabs 可退出筛选。 |
| 关注时间 | 在空间页“全部关注”列表补充 relation 接口提供的精确关注时间。 |
| 扩展弹窗 | 展示置顶数量和最后数据更新时间；时间不代表云端同步完成。 |

## 数据与约束

- UP 身份使用真实数字字符串 `mid`；头像和昵称仅用于展示，历史头像 URL 规范化为 HTTPS。
- 置顶列表以 `chrome.storage.sync` 为权威，成功写入后镜像到 local；v4 按真实 mid 分键保存置顶/取消记录，排序独立保存，兼容 v3/v2/v1。缺少某个 UP 的记录不代表取消，排序也不改变置顶成员。
- 新设备收到同步数据前可以暂时显示空列表，打开页面不写空状态；随后新增/取消某个 UP 只写对应记录，不覆盖其它 UP。不同 UP 的离线操作可以共存；同一个 UP 及排序的并发冲突以浏览器最终同步的记录为准。所有设备须升级到 v1.2.3；旧版本不能识别 v4 操作。
- 仅 sync 无可用置顶数据时回退旧 local；合法空列表和取消记录仍为权威。只读不上传，在用户首次置顶、取消或排序时将已读到的旧状态按 mid 迁移。若旧列表只存在 local，需在保有数据的旧设备操作后才会上传。
- 超出 sync 单项/总字节/键数配额时拒绝本次置顶并给出页面提示，不保存为仅本机可见的置顶状态。取消记录保留以避免旧状态复活，也占用 sync 键数配额。UI 偏好也通过 sync/local 持久化。
- 菜单和按钮尽量沿用 B 站原生容器及样式；页面 API 缓存仅服务当前页面，不自动写回置顶数据。

## 开发与验收入口

页面调查和注入逻辑调试默认使用 Codex 内置浏览器，复用 B 站登录态，通过实时 DOM、页面交互及可用开发接口验证，无需用户预先保存 HTML。本地 MV3 扩展由用户通过内置浏览器的“管理扩展程序”界面加载构建目录，Agent 随后检查实际注入和运行行为；当前自动化工具不能代办加载/重载。完整 storage bridge 和跨设备同步以实测为准，页面注入或临时存储替身不代替真实扩展验收。具体能力与账号操作边界见维护指南。
